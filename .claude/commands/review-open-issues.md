# Review Open Issues After Completion

After completing an issue, review remaining open issues to provide contextual comments about how the completed work impacts implementation approaches, provides new patterns to follow, and creates alignment opportunities.

## 📋 WORKFLOW STEPS

### Phase 1: Parse Arguments and Determine Scope
**🔍 Analyze completed work and identify issues to review:**

1. **Parse Arguments**: Extract from `$ARGUMENTS`:
   - **Required**: Completed issue number (e.g., "88")
   - **Optional**: Issues to review (e.g., "89-95", "all", "related")
   - **Optional**: Project context (e.g., "U10-site")

2. **Analyze Completed Issue**: 
   ```bash
   gh issue view [completed-issue] --repo stewmckendry/hockey_coach --json number,title,body,comments,labels,url
   ```
   - Extract what was implemented
   - Identify new patterns, utilities, or approaches created
   - Note database changes, dependencies, or architectural decisions

3. **Determine Issues to Review**:
   - If "all": Get all open issues
   - If "related": Filter by similar labels/project context
   - If range (e.g., "89-95"): Specific issue numbers
   - If none specified: Use project context to filter relevant issues

4. **Fetch Target Issues**: Get details for each issue to review
   ```bash
   gh issue list --repo stewmckendry/hockey_coach --state open --json number,title,url,labels,assignees,updatedAt
   ```

### Phase 2: Gather Implementation Context
**📚 Build comprehensive understanding of existing work:**

1. **Identify Completed Related Work**: 
   - Search for recently closed issues in same area
   - Review recent commits and changes
   - Identify patterns and established approaches

2. **Analyze Current Codebase State**:
   - Use Grep/Glob to find relevant existing code
   - Identify shared utilities and patterns
   - Note recent architectural decisions

3. **Create Context Summary**: Document key findings:
   - Recently completed features that relate
   - Established patterns to follow
   - Available utilities and helpers
   - Common dependencies and integrations

### Phase 3: Review Each Open Issue
**🔎 Detailed analysis of each issue:**

For each issue to review:

1. **Fetch Full Issue Details**:
   ```bash
   gh issue view [issue-number] --repo stewmckendry/hockey_coach --json number,title,body,comments,labels,url,assignees
   ```

2. **Analyze Issue Content**:
   - Parse issue description and requirements
   - Review existing comments and discussions
   - Identify implementation complexity
   - Note any blockers or dependencies

3. **Identify Relationships**:
   - Dependencies on other open issues
   - Similarities to completed work
   - Opportunities for code reuse
   - Potential conflicts or overlaps

4. **Assess Implementation Approach**:
   - Recommend existing patterns to follow
   - Suggest utilities or libraries to use
   - Identify potential challenges
   - Estimate complexity level

### Phase 4: Generate Contextual Comments
**💬 Create helpful implementation guidance:**

For each issue, generate a comment that includes:

**Template Structure:**
```markdown
## 🔍 Implementation Context & Guidance

### Related Work
- **Recently Completed**: [List relevant completed features/issues]
- **Existing Patterns**: [Point to similar implementations in codebase]
- **Available Utilities**: [Highlight reusable code/tools]

### Implementation Recommendations
- **Architecture**: [Suggest approach based on existing patterns]
- **Dependencies**: [List established libraries/tools to use]
- **Integration Points**: [How this connects to existing systems]

### Considerations
- **Dependencies**: [List issues this depends on or blocks]
- **Complexity**: [Estimate: Simple/Medium/Complex]
- **Alignment**: [How this fits with project architecture]

### Code Locations
- **Similar Features**: [File paths to reference]
- **Utilities to Use**: [Specific functions/modules]
- **Tests to Model**: [Existing test patterns]

### Next Steps
- [ ] [Specific implementation steps based on existing patterns]
- [ ] [Testing approach recommendations]
- [ ] [Documentation updates needed]

---
*Review generated by /review-open-issues command - based on analysis of existing codebase and recently completed work*
```

### Phase 5: Post Comments and Summary
**📝 Deliver guidance to development team:**

1. **Post Individual Comments**: 
   ```bash
   gh issue comment [issue-number] --body-file [comment-file]
   ```

2. **Generate Overall Summary**:
   - Issue prioritization recommendations
   - Dependency ordering suggestions
   - Resource allocation insights
   - Common patterns identified

## 🎯 SPECIALIZED CONTEXTS

### U10 Hockey Team Site Context
When reviewing U10 site issues, focus on:
- **Content Creation Workflow**: Integration with `/research-hockey`, `/draft-content`, etc.
- **UX Guidelines**: Age-appropriate content standards (70% visual for U10)
- **MCP Integrations**: Usage of Notion, Exa, YouTube, Stability AI, etc.
- **Database Schema**: Team Information, Content Library structures
- **Notion Templates**: Established page formats and structures

### Development Infrastructure Context
When reviewing dev infrastructure issues:
- **Service Architecture**: MCP servers, web app, vector database
- **Testing Patterns**: Existing test suites and validation approaches
- **Deployment Processes**: Current CI/CD and environment setup
- **Documentation Standards**: CLAUDE.md patterns and conventions

## 🚨 REVIEW QUALITY STANDARDS

### Helpful Comments Should:
- ✅ Reference specific existing code locations
- ✅ Suggest concrete implementation approaches
- ✅ Identify potential challenges early
- ✅ Recommend established patterns and utilities
- ✅ Clarify dependencies and relationships
- ✅ Provide actionable next steps

### Avoid Comments That:
- ❌ Are too generic or vague
- ❌ Duplicate information already in the issue
- ❌ Make assumptions without codebase evidence
- ❌ Overwhelm with too much detail
- ❌ Contradict established project patterns

## 📊 SUCCESS CRITERIA

The review is complete when:
1. ✅ All targeted issues have been analyzed
2. ✅ Contextual comments posted with specific guidance
3. ✅ Implementation relationships identified
4. ✅ Existing patterns and utilities highlighted
5. ✅ Summary report generated with prioritization insights
6. ✅ Development team has clear guidance for alignment
