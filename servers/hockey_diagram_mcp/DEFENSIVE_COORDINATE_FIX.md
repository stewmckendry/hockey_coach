# Defensive Coordinate Mapping Fix

## Issue Summary

**Problem**: The two-stage parser was failing to generate proper defensive formations, falling back to basic formations instead of using the advanced coordinate mapping system.

**Root Cause**: A bug in the `_validate_and_correct()` method in `two_stage_parser.py` was causing a KeyError when trying to validate zone areas.

## Root Cause Analysis

### The Bug

In `two_stage_parser.py` at line 554, the code was attempting to validate zone areas against a locations dictionary:

```python
if isinstance(zone.get("area"), str) and zone["area"] not in self.DEFINITIONS["locations"]:
    logger.warning(f"Invalid location: {zone.get('area')}, defaulting to slot")
    zone["area"] = "slot"
```

**Problem**: The `DEFINITIONS` dictionary does not contain a "locations" key. The locations are generated dynamically by the `_get_zone_aware_locations()` method based on the zone context (defensive, offensive, neutral).

### Error Manifestation

This caused the two-stage parser to fail with the error:
```
Two-stage parsing failed: 'locations'
```

When this happened, the system would fall back to the basic formation generator, which worked correctly but didn't provide the advanced tactical formations that users requested.

### Why the Basic Coordinates Were Correct

The coordinate mapping system itself (`coordinate_mapper.py`) was working correctly:
- Defensive zone coordinates: negative X values (-100 to -25)
- Offensive zone coordinates: positive X values (25 to 100)
- Neutral zone coordinates: X values around 0 (-25 to 25)

The fallback formation generator used these coordinates correctly, which is why the test showed proper negative X values for defensive formations, but the titles indicated "Basic Formation - Fallback".

## The Fix

### Code Changes

**File**: `two_stage_parser.py`
**Lines**: 553-556

**Before**:
```python
# Validate area if it's a named location
if isinstance(zone.get("area"), str) and zone["area"] not in self.DEFINITIONS["locations"]:
    logger.warning(f"Invalid location: {zone.get('area')}, defaulting to slot")
    zone["area"] = "slot"
```

**After**:
```python
# Validate area if it's a named location
# Note: locations are dynamically generated, so we'll skip validation here
# The coordinate mapper will handle invalid locations
pass
```

### Rationale for the Fix

1. **Dynamic Location Generation**: Locations are generated by `_get_zone_aware_locations()` based on context zone (defensive/offensive/neutral).

2. **Coordinate Mapper Validation**: The `coordinate_mapper.py` already has robust validation and fallback mechanisms for invalid locations.

3. **Avoiding Duplication**: Rather than duplicating location validation logic, we let the coordinate mapper handle it.
